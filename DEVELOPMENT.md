# Development and validation

Use Claude Code 2.1.287 or later and Node.js 24 or later for development. TypeScript is the only npm dependency, used to check the installed Claude SDK. Installed mods need neither npm nor a build step.

```sh
npm ci
claude --plugin-dir ./plugins/night-feast
```

Exit that session, then copy the SDK declarations generated by Claude:

```sh
npm run sdk-types
npm run prepare
npm run typecheck
npm run validate
npm test
npm run integration
npm run previews
```

The [Claude authoring guide](https://code.claude.com/docs/en/plugins/mods/create#get-type-definitions-for-your-version) explains the generated declarations. They are ignored because they describe the local Claude build and may include connected-tool types.

Edit `shared/`, then run preparation. The installed copies under `plugins/*/hooks/shared/` are committed release inputs. They must be current before publishing. Each manifest's types file is self-contained. All runtime imports remain inside that plugin's directory.

`npm test` invokes `claude plugin test` for every plugin. Tests exercise real hook dispatch, UI element validation, and client modules without network or sign-in. The integration harness copies the scene and analysis logic into self-contained inline test plugins because Claude's test transport does not retain imported module bindings. It uses direct state operations in place of the equivalent SDK atom helpers. Gameplay is tested separately in Night Feast's unmodified client module.

The native validators inspect every plugin's hooks, SDK calls, and state references. TypeScript checks the same SDK used by the installed CLI. Preview generation calls the pure scene renderers and useful-view renderer with synthetic state.

## Isolated installation

```sh
npm run smoke:install
```

This registers the local marketplace and installs all six plugins into a temporary `CLAUDE_CONFIG_DIR`. It prints the inspection directory and leaves the temporary files available for review. It does not change your installed plugin configuration.

## Real provider smoke test

```sh
npm run smoke:model
```

This uses your existing Claude authentication with user/project settings excluded and MCP servers disabled. It creates a temporary cart project, loads all six plugins, requests two edits, and runs two Node tests. A temporary observer records only the summary model settings and success flags. The turn has a one-dollar main-session budget and a 55-second process timeout. Provider calls from mods use the request and token limits implemented by the mods.

The project and report remain in the printed temporary directory. This command may persist progress through the tested plugins' local stores. It requires a Claude login and working provider access. No credentials are copied into the repository or temporary configuration.
